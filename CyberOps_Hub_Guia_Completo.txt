CYBEROPS HUB — GUIA COMPLETO DO PROJETO
Projeto de portfólio alinhado ao AIR Fellowship — AI-Driven Fullstack Development

============================================================
1. VISÃO GERAL
============================================================

Nome: CyberOps Hub

Objetivo:
Criar uma plataforma web de gerenciamento de incidentes de segurança
para uma empresa, permitindo registrar, investigar, acompanhar e encerrar
incidentes, administrar ativos, evidências, usuários e auditoria.

O projeto também servirá como laboratório prático para aplicar, ao longo
da evolução, os conceitos previstos no AIR Fellowship:
- Git, branches e Pull Requests
- HTML/CSS/JavaScript e TypeScript
- Testes unitários, integração e E2E
- Regex para validação
- Node.js e NestJS
- React.js
- MongoDB
- Docker
- Postman
- Prompt Engineering e Context Engineering
- Skills, Agents e MCP
- AGENTS.md e governança de agentes
- Spec-Driven Development
- Spec Kit e EARS
- CI/CD e Quality Gates
- OWASP, secrets e dependências
- Deploy em containers
- AWS e arquitetura escalável

IMPORTANTE:
O objetivo não é implementar tudo de uma vez. O projeto deve evoluir
gradualmente conforme os conhecimentos forem aprendidos.

============================================================
2. PROBLEMA QUE O SISTEMA RESOLVE
============================================================

Uma empresa precisa centralizar seus incidentes de segurança.

Exemplo:
Um servidor começa a apresentar centenas de tentativas de login
malsucedidas. O analista registra o incidente, classifica sua severidade,
associa o ativo afetado, adiciona evidências, registra ações realizadas
e acompanha o incidente até o encerramento.

O CyberOps Hub centraliza esse processo.

7. CYBEROPS AI
============================================================

A IA não deve ser implementada antes do MVP funcionar.

Objetivo:
Auxiliar o analista na análise de incidentes.

Exemplo de entrada:

"Foram detectadas 350 tentativas de login falhas contra o servidor
SSH em aproximadamente 5 minutos, provenientes do mesmo endereço IP."

A IA pode sugerir:

Classificação:
Brute Force

Severidade:
Alta

Resumo:
"Atividade compatível com tentativa automatizada de força bruta
contra serviço SSH."

Ações sugeridas:
1. Verificar logs de autenticação.
2. Validar possível comprometimento de credenciais.
3. Bloquear ou limitar o endereço de origem.
4. Verificar outros ativos.
5. Avaliar rotação de credenciais.

IMPORTANTE:
A IA deve sugerir, não tomar decisões críticas automaticamente.
O analista aceita ou rejeita a sugestão.

============================================================
8. CYBEROPS AGENT
============================================================

O CyberOps Agent será a evolução do módulo de IA.

Objetivo:
Permitir que um agente autorizado consulte informações do sistema e
auxilie na investigação de incidentes.

Exemplo:

Usuário:
"Analise o incidente INC-0042."

O agente pode:
1. Buscar o incidente.
2. Buscar evidências permitidas.
3. Consultar o ativo afetado.
4. Consultar a timeline.
5. Analisar as informações.
6. Produzir uma avaliação.
7. Sugerir classificação.
8. Gerar recomendações.

O agente NÃO deve possuir acesso irrestrito.

============================================================

11. MCP
============================================================

Criar ferramentas controladas para o agente:

get_incident()
get_asset()
get_incident_timeline()
get_audit_logs()
search_incidents()

O agente acessa essas ferramentas conforme suas permissões.

Exemplo:

CyberOps Agent

READ:
[OK] incidents
[OK] assets
[OK] evidence metadata

WRITE:
[OK] incident notes

DELETE:
[BLOCKED]

A ideia é demonstrar governança e controle de ferramentas.

## Architecture

## Testing
- Novas features exigem testes.
- Não modificar testes apenas para fazê-los passar.
- Executar testes antes do PR.

## Pull Requests
- Explicar alterações arquiteturais.
- Incluir evidências de testes.
- Registrar considerações de segurança.

16. SEGURANÇA
============================================================

- JWT
- RBAC
- validação de entrada
- sanitização
- rate limiting
- CORS adequado
- headers de segurança
- tratamento seguro de erros

Secrets:
- nunca colocar credenciais no Git
- usar variáveis de ambiente
- futuramente usar AWS Secrets Manager ou Parameter Store

Dependências:
- verificar vulnerabilidades
- atualizar dependências
- executar scans no CI

Docker:
- evitar imagens desnecessariamente privilegiadas
- não incluir secrets
- reduzir superfície de ataque
